# result-export-and-recovery Specification

## Purpose
定义提示词与完整结果复制、原生多格式导出、批量 ZIP、解密原图提示、部分结果权限以及错误诊断和恢复操作的稳定行为。
## Requirements
### Requirement: 复制权限必须区分部分结果和最终结果

应用 SHALL 允许停止、失败或断流后的部分内容复制当前已接收提示词，但只有严格完成的结果或正式修订才能复制完整结果和执行正式导出。

#### Scenario: 复制流式部分提示词

- **WHEN** 请求停止但已经收到部分提示词
- **THEN** 用户可以复制当前提示词，复制完整结果和导出保持不可用

### Requirement: 单项导出必须支持稳定格式

应用 SHALL 支持 Markdown、`schemaVersion: 2` 的结构化 JSON 和纯提示词文本；所有格式必须导出当前活动修订，时间统一为本地 `yyyy-MM-dd HH:mm:ss`，无效时间显示 `--`。

#### Scenario: 导出结构化结果

- **WHEN** 用户导出当前活动修订为 JSON
- **THEN** 文件包含稳定 Schema 2、摄影测定、白名单实拍信息、活动提示词与元数据，不包含原图路径或敏感正文

### Requirement: 批量导出必须由 Rust 生成受限 ZIP

应用 SHALL 允许一次导出 1 至 100 个任务，可选择 Markdown、JSON、纯文本和是否包含原图；ZIP 必须在目标目录内使用排他创建且权限为 `0600` 的临时文件，成功后原子替换目标。

#### Scenario: 批量导出包含原图

- **WHEN** 用户明确选择在 ZIP 中包含原图
- **THEN** 应用先提示图片将以未加密形式写出，再由 Rust 解密并写入用户选择的保存位置

#### Scenario: ZIP 写入失败

- **WHEN** 批量导出在完成前失败
- **THEN** 临时明文被清理，已有目标文件不被截断或替换

### Requirement: WebView 不得控制任意导出路径

结果、原图、日志和诊断导出 SHALL 由 Rust 打开原生保存对话框并完成写入，WebView 不得传入或接收任意本机路径。

#### Scenario: 用户取消保存对话框

- **WHEN** 用户关闭原生保存对话框而未选择位置
- **THEN** 命令返回取消状态且不创建文件，不作为应用错误提示

### Requirement: 可恢复错误必须提供持久操作

模型、原图、历史或导出错误 SHALL 在相关工作区持续显示稳定错误码，并按可用能力提供重试、打开设置、查看关联日志和导出脱敏诊断；需要用户决策的错误不得只使用短暂 Toast。

#### Scenario: 模型请求失败

- **WHEN** 任务因认证、限流、超时或断流失败
- **THEN** 结果区保留已有内容和错误操作，用户可以重试或查看同一 request ID 的日志
