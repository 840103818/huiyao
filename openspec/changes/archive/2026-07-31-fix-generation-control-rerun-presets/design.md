## Context

当前单图生成使用 `generationState`、单个 `interactionId` 和 `cancelRequestedRef`，项目队列则额外维护 `queueRunning`、`queuePausedRef`、`queueStopRef` 与活动 ID 集合。两个停止入口没有共享同一生命周期：停止发生在请求 ID 建立前时无法取消后来启动的请求，队列停止还会在工作线程真正结束前恢复 UI。

已完成任务的重新生成通过复制任务再执行队列流程实现，SQLite 状态机同时禁止 `completed` 重新进入 queued。预设 Modal 的两个 Select 被原生 `label` 包裹，真实浏览器会把一次点击再次转发到内部 input，导致菜单打开后立即关闭；现有 jsdom 测试未覆盖浏览器标签激活语义。

实现必须保持现有 IPC、SSE 事件、SQLite Schema、原图关联和浏览器降级契约。参见 proposal.md 和本变更的三个 capability delta。

## Goals / Non-Goals

**Goals:**

- 用一个前端操作生命周期协调直接生成、重新分析和批量队列的开始、停止与收尾。
- 在停止发生于任意阶段时阻止迟到请求、兼容回退、自动优化和下一队列任务继续执行。
- 不修改数据库结构即可让已完成任务安全复用原任务，并在失败时保留旧结果。
- 修正预设控件的 HTML 语义、焦点和真实浏览器行为。

**Non-Goals:**

- 不实现模型 SSE 断点续传，也不把暂停状态描述为传输层暂停。
- 不增加任务状态、IPC 命令、serde 字段或运行时依赖。
- 不改变并发上限、预设快照格式、显式创建副本和原图存储机制。

## Decisions

### 1. 使用统一停止协调器而不是继续拼接两个停止函数

在应用状态层维护一次分析运行的稳定标识、`running/stopping/idle` 生命周期、停止锁存和活动 interaction ID 集合。直接生成、原任务重跑和队列工作线程都通过同一协调器登记请求与检查停止状态。

停止流程按以下顺序执行：

1. 原子地锁存停止意图并进入 `stopping`，使队列不再取出任务。
2. 取消当前集合中的全部 interaction ID。
3. 请求回调收到迟到的 `started` 时，先检查锁存并立即调用现有取消 IPC，不再处理 delta 或 fallback。
4. 图片准备完成后、反推开始前、反推完成后和自动优化开始前再次检查锁存。
5. 等待所有活动 Promise 退出、打印缓冲追平并完成 paused 状态写入。
6. 清理 ID、锁存和计时器，最后进入 `cancelled` 并恢复操作。

选择前端协调器是因为 Rust 已经按 interaction ID 正确持有 `CancellationToken`，问题发生在请求尚未登记和前端过早结束生命周期。替代方案是新增“取消所有请求”IPC，但会扩大命令面，也无法单独解决队列继续取任务和 UI 提前解锁。

### 2. 操作互斥以应用命令状态传递，不使用遮罩层拦截

从统一生命周期派生 `analysisLocked`，显式传给 Toolbar、ProjectTaskSidebar、ImageWorkbench、ResultsWorkspace 及快捷命令入口。控件保留稳定尺寸和可访问名称，但设置为 disabled 或不渲染；唯一的停止按钮保持可聚焦。正文滚动、文本选择和真实进度展示不被禁止。

进入分析前关闭参数、预设或其他会修改上下文的弹层；分析期间不允许再打开设置、日志、查看器或 Drawer。`Cmd/Ctrl+Enter` 和 `Esc` 在锁定期间都映射到同一停止流程，重复停止调用必须幂等。使用显式 disabled 可被键盘和辅助技术识别，优于依靠透明遮罩和 `pointer-events`。

### 3. 已完成任务重跑保持持久状态为 completed，成功后原子替换结果

重新分析开始时不把已完成任务写回 queued/running，避免修改现有状态机以及应用异常退出后留下“有旧结果但状态 paused”的歧义。前端用 `rerunningTaskId` 为任务行和当前工作台呈现临时“重新分析中”状态；SQLite 中旧 `result_json` 和 completed 状态保持不变。

新请求严格成功后调用现有任务结果更新命令，以单次 SQLite UPDATE 替换同一任务的结果；停止、失败或断流只结束临时运行状态并展示本次错误，绝不写入部分结果。任务 ID、任务数量、原图、收藏、标签、标题和父任务关系均不变化。显式“创建关联副本”继续调用现有复制命令，但与默认“重新分析”分开命名和入口。

选择成功后替换而不是让 completed 重新进入队列，是为了获得天然回滚和崩溃安全，同时避免 Schema 迁移。代价是持久化列表在请求过程中仍为 completed；前端必须用临时状态准确标识当前任务，后台重启后旧结果仍保持一致。

### 4. 预设字段使用非 label 容器和显式无障碍关联

将包裹 Select 的原生 `label` 改为普通字段容器，字段标题使用稳定 ID，并通过 `aria-labelledby` 关联 Select。弹层继续使用现有全局 Trigger 层级，不再依赖针对该 Modal 的 `triggerProps` 和局部 z-index 补丁。

测试除选择值变化外，还要断言 Select 不是 label 的后代；真实浏览器验证单击只产生一次激活、菜单可见可点击，键盘可打开并确认，Modal 关闭后焦点返回预设编辑按钮。

### 5. Rust、IPC 与浏览器降级保持兼容

现有 `cancel_reverse_prompt`、`update_project_task_result` 和任务状态更新命令足以支持设计，不新增 IPC。Rust 继续负责真正的 HTTP 取消、响应限制和结果写入；前端负责停止锁存与调用时序。浏览器预览不发起真实请求，但需要提供锁定和预设交互状态以覆盖视觉与组件验证。

## Risks / Trade-offs

- [停止与 started 同时发生仍可能竞态] → 登记 started 时先读取停止锁存，登记和取消都使用同一同步路径，并为停止前、停止中、停止后到达事件建立确定性测试。
- [两个并发工作线程重复更新队列终态] → 由唯一协调器等待全部 worker，并集中执行最终 paused 写入和列表刷新。
- [重新分析期间数据库仍显示 completed] → 仅对当前应用会话使用 `rerunningTaskId` 覆盖显示；异常退出无需恢复临时状态，旧结果仍有效。
- [禁用范围过宽影响阅读] → 只禁用命令和上下文切换，保留滚动、文本选择、实时状态与停止按钮；在 1440x900 和 1120x720 明暗主题下验证焦点与可见性。
- [移除局部 z-index 后其他弹层回归] → 依赖已有全局 Arco 层级，并在 Modal 内分别验证鼠标、键盘、浅色和深色主题。

## Migration Plan

1. 先加入协调器、竞态测试和互斥状态，不改变持久化格式。
2. 切换重新分析入口并验证任务数量、任务 ID 和失败回滚。
3. 修正预设 DOM 结构与交互测试，删除失效的局部层级补丁。
4. 更新用户说明、前端架构、交互规范和脱敏 UI 基线后执行全量验证。

本变更没有数据迁移。回滚时可恢复原前端控制器和副本式重新生成行为，SQLite、原图和结果数据不需要转换。
